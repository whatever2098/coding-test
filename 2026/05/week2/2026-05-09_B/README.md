# 문제 이름
leetcode 994 Rotting Oranges

## 🧩 내 코드의 의도 & 틀리는 반례
- 멀티 소스 BFS의 의도를 가지고 있다.

1. 격자를 한 번 훑으면서
- 신선한 오렌지 1의 개수는 fresh에 저장
- 썩은 오렌지 2의 위치는 큐 q에 저장
2. 큐에 들어 있는 썩은 오렌지들을 기준으로 주변 신선한 오렌지를 썩게 만듦
3. 신선한 오렌지가 모두 사라지면 걸린 시간 minute 반환
4. 끝까지 썩지 못한 신선한 오렌지가 남으면 -1 반환

문제는 처음부터 썩은 오렌지가 여러 개 있을 수 있으므로, 모든 썩은 오렌지를 큐에 넣고 동시에 퍼뜨리는 멀티 소스 BFS로 푸는 게 정답이다.

## 왜 틀렸는지
# 이유1. 주변 칸으로 이동하지 않음.
```cpp
int nx = q.front().first;
int ny = q.front().second;
```
4방향 확인을 제대로 못하게 된다.

```cpp
int x = q.front().first;
int y = q.front().second;
q.pop();

for(int dir = 0;dir < 4;dir++){
    int nx = x + dx[dir];
    int ny = y + dy[dir];
}
```
# 이유 2. rotted = q.size() 위치가 잘못됨.
BFS에서 매 분마다 큐 크기가 달라진다. 새로 썩은 오렌지가 큐에 추가되기 때문. 그래서 rotted = q.size()는 while문 바깥이 아니라 매 분 시작 시점마다 다시 계산해야 한다.

# 이유 3. minute++ 위치가 잘못됨.
1분은 오렌지 하나가 바뀌는 시간이 아니라, 현재 썩은 오렌지들이 동시에 주변을 썩게 만드는 한 턴이다.

따라서 minute++는 한 레벨, 즉 현재 큐 크기만큼의 처리가 끝난 뒤에 해야 한다.
## ⏱️ 시간 복잡도
 # O(M * N)

## 문제 유형
- 최단 시간 시뮬레이션, 멀티 소스 BFS

## 🔁 다시 풀면 이렇게 한다(복기 문장)
- 처음부터 썩은 오렌지를 모두 큐에 넣고, 현재 큐 크기만큼을 1분 단위로 처리한다. 새로 썩은 오렌지는 다음 레벨에서 처리해야 하므로 q.size()를 매 분마다 저장하고, minute++는 그 레벨 처리가 끝난 뒤 한다.
