# 문제 이름
codeforces 520B Two Buttons

## 🧩 내 코드의 의도 & 틀리는 반례
- n이 m보다 작으면 일단 계속 2배 해서 m 이상으로 만든 뒤, 초과한 만큼 -1을 해서 맞춘다.

- 즉, 버튼 사용을 이렇게 나눠 생각했다.

>빨간 버튼: n을 m 이상으로 만들 때까지 사용
>파란 버튼: n이 m보다 커진 만큼 사용

- 4 -> 6이 4->8->7->6으로 3번 움직인다 생각했는데, 반례로 4->3->6의 2번으로 완성시킬 수 있었다.

## 왜 틀렸는지
- 이 문제는 단순히 2배를 최대한 많이 한다가 항상 최적이 아니다.

- 실제 최적 경로에서는 중간에 파란 버튼을 먼저 눌러서 숫자를 줄인 뒤, 그 값을 2배 하는 게 더 빠를 수 있다.

>앞으로 가면서 “언제 2배하고 언제 -1할지”를 정하는 것은 까다롭다.
>그래서 앞에서부터 무작정 2배하는 그리디는 실패했다.

## 💡 핵심 아이디어
- 이 문제는 거꾸로 생각하면 쉬워진다.
- 목표값 m에서 시작해서 n으로 되돌아간다고 생각하면 반대 연산은 다음과 같다.

```cpp
x → x / 2     // x가 짝수일 때
x → x + 1
```
따라서 m에서 n으로 줄여가면 된다.

m > n인 동안
m이 짝수라면:

```cpp
m /= 2
```
m이 홀수라면:
```cpp
m += 1
```
왜냐하면 홀수는 바로 2로 나눌 수 없기 때문이다.

예를 들어 m = 17이면:
17 → 18 → 9 → 10 → 5
이렇게 가는 식이다.

m <= n이 되면
이제 원래 방향에서는 n에서 m까지 파란 버튼으로 1씩 줄이면 된다.

따라서 남은 횟수는:

```cpp
n - m
```

## ⏱️ 시간 복잡도
- 반복 횟수는 대략 m을 계속 2로 나누는 횟수에 비례한다.
# O(log m)

## 🔁 다시 풀면 이렇게 한다(복기 문장)
- 이 문제는 앞에서부터 2배를 최대한 많이 한다로 풀면 중간에 -1 후 2배가 더 좋은 경우를 놓친다.
따라서 n → m으로 가는 대신 m → n으로 거꾸로 생각해서, 짝수면 /2, 홀수면 +1을 하는 그리디로 해결해야 한다.
